# 记忆系统

> 这一页讲「助手为什么能记住事、记在哪、怎么找回、怎么忘掉」。
> 2026-11-07 晚做过一次大改（记忆系统 P1）；本文是该轮改版的公开说明，验收细节在仓库外的本地 RUNBOOK / 执行计划里。

---

## 一句话设计

**写入口优先于召回**：每条消息先落盘，再谈智能；每轮只注入「今天最近几条 + 记忆提示」，历史靠按需检索；摘要只做入口，原文永远保留；忘记 = 硬删除。

来源是两派经验的互补：

- **分层生命周期**（人设 / 事实 / 日记 / 会话分层，只清会话，其余落文件）；
- **最简检索 + 可观测性**（SQLite FTS5 全文检索；写入口计数、同步延迟、失败要冒泡，不静默）。

---

## 分层结构

| 层 | 内容 | 存储位置 | 写入 | 读取 | 保留 |
|---|---|---|---|---|---|
| L0 人设 | 助手是谁、怎么说话、红线 | `persona-modes.json` / `directPrompt` | 人工编辑 | 每轮 | 永久 |
| 流水 journal | 每条消息原文 | `%USERPROFILE%\.dsh\weixin\extras\journal\YYYYMMDD.jsonl` | 实时 | 写日记/召回/排查 | 60 天 |
| 日记 diary | 滚动 brief（≤30min）+ 日终 daily + 手写 note | `%USERPROFILE%\.dsh\weixin\extras\memory\` | 定时/每轮后/主动 | 新会话注入一次 | 90 天 |
| 核心事实 facts | 用户确认过的偏好/约定/日期 | `%USERPROFILE%\.dsh\weixin\extras\memory\facts.json` | 助手提议 → 用户「记下」→ 确认 | 每轮注入 core | 永久 |
| 会话 | DSH 对话历史 | DSH 会话日志 | 自动 | 主上下文 | 可压缩 |
| 检索层 | 可检索知识库（FTS5） | `fish/memory/kb.db` | 每 10 分钟增量 sync | `memory_recall` 等工具 | 跟流水/日记 |

写入路径：

```
消息 → journal（必写）→ brief/daily 日记（滚动压缩）→ KB 索引
                                   ↓
每轮上下文 ← 今日最近 8 条 + 记忆提示（约 600 字）
问到过去 → memory_recall（跨天）/ memory_today / memory_search → 原文片段
```

## 核心决策（已拍板）

1. 用户说「记下 / 确认 / 记住」= **核心事实确认**；助手只能提议候选，不能自己写 core。
2. **核心事实永久**；流水类日记 90 天；journal 原文 60 天；备份滚动 7 天。
3. **忘记 = 硬删除**：facts / KB / diary / journal 同步删，delete-ledger 防复活，reindex 和 sync 都不得把已删内容带回来。
4. **不接 Notion / IMA**：网络与 API 通路不稳，运行时记忆统一走本地知识库；Notion 不做导出镜像。
5. **先 FTS 再向量**：SQLite FTS5 + 中文 2-gram + BM25 + 时间衰减（e 折 45 天）；`embedding` 列预留，数据量上来再评估混合检索。
6. **隐私口径**：敏感内容可留本地 journal 便于删除/对账，但**不入 KB、不进注入**；journal 可配脱敏；备份 7 天滚动。
7. **可观测性是一等公民**：写入口计数、sync 新鲜度、检索延迟、失败必须显式报错；外部哨兵定期自检。

## 什么时候该"想起来"

默认不查（省 token、更像人）：闲聊、打招呼、接梗。

必须查（先查再答，不许"记不清了"）：

1. 提到「上午 / 之前 / 上次 / 那天 / 我说过」等时间锚点；
2. 问「你还记得吗 / 说过什么」；
3. 纠正助手的记忆（「不对，是…」）→ 先查最近相关主题再修正；
4. 涉及约定、日期、金额、承诺、隐私边界；
5. 跨天/跨会话的连续性话题。

查什么：今天 → `memory_today`；跨天/模糊 → `memory_recall`（k=5，按相关+新近）；精确某天 → `memory_search(query, days)`。

## 检索实现

- **中文 2-gram 分词**：FTS5 默认分词不支持中文，2-gram 让口语、梗、错别字也能命中。
- **BM25 + 时间衰减**（e 折 45 天）排序，取 top k。
- 写入按 `sha1(source|ts|text)` 去重，重复 sync 不重复入库。
- 实测（2026-11）：文档数百条、噪声 0、敏感 0；引擎内 p50 ≈ 1ms、p95 ≈ 1.6ms；工具端（含子进程启动）≈ 70–200ms。
- embedding 预留：`embedding BLOB` 列已建；后续接 DashScope `text-embedding-v4`（已探活通过 dim=1024）或本地 bge，加分支即可，不迁数据。

常用工具：`memory_today`、`memory_recall`、`memory_search`、`memory_health`、`memory_propose` / `memory_confirm`、`memory_forget` / `memory_forget_confirm`、`memory_prune`。

## 这一轮改了什么（2026-11-07 晚）

- **写入口**：journal 必写 + 对账补漏 + 每日回填；敏感/系统消息过滤（B8）。
- **日记**：brief ≤30min、daily 22:00、错过补写；保留期与 prune。
- **核心事实**：候选 → 用户「记下」→ core（永久），双闸 + 否定排除 + supersede；已通过 9/9 eval。
- **检索**：本地 FTS5 知识库上线（`kb.py`），每 10 分钟增量 sync，`memory_recall` 可用。
- **删除**：`memory_forget` dry-run 清单 → 用户确认 → 事务删除 + delete-ledger + reindex 防复活（实测四库 0 残留）。
- **血缘**：journal 行加 msg_id；brief/daily 记 derived_msg_ids；KB docs 记 source_ref（删除/去重/追溯的前提）。
- **可观测**：`memory_health`（写入口计数/同步滞后/检索延迟/注入字数/摘要占用）+ `metrics.json` + `eval_kb.py` 动态测试集。
- **哨兵**：记忆链路外置看护（每 10 分钟），补齐"社交 daemon watchdog 只覆盖浏览器"的盲区。
- **成本护栏**：每轮注入压到约 900 字（今日流水 8 行 + 核心事实 + 记忆提示），日记只在新会话注入一次（≤6000 字）；表情名单改按需查，省约 1.1k tokens/轮。

## 已知限制

1. embedding 混合检索尚未上线（C5.0 探活已过，C5.1 对比未做）。
2. QQ 官方机器人 / AstrBot 的旧记忆尚未并入同一 KB（跨通道导入是 P2）。
3. 自动 prune 已接 tick，但长期效果仍需抽检（lastPruneDay）。
4. 「忘记」依赖 delete-ledger；若手工清库，需先检查台账，避免 reindex 复活。
5. 敏感过滤规则（filters.json）由用户审定，新类型要手动补充。
