## 1. 记忆系统

五层结构、检索、遗忘、可观测性与运维，详见 [记忆系统](记忆系统.md)。本轮要点：

- 写入口优先：每条消息先落 journal，再谈智能；
- 摘要只做入口，原文保留；核心事实需用户确认；
- 忘记 = 硬删除（delete-ledger 防复活）；
- 本地 FTS5 知识库 + 每 10 分钟增量同步；`memory_recall` 等工具按需检索；
- 外置哨兵每 10 分钟自检（同步新鲜度 / 记忆健康 / 当日 journal）。

## 2. 表情包

- 桥内 300 张 / 31 场景（manifest + 备份 + 定期 drift 自愈）；AstrBot 图库 21 类。
- 发送：优先 `sticker_pick`（返回图片路径）；写 `[表情:名字]` 前必须 `sticker_names(category=…)` 查真名，**不要自造名字**（写错会变文字）。
- 一次最多 2 张，每 2–3 条回复配 1 张；微信桥只显示静态图，QQ 官方 Bot 支持 GIF。

## 3. 社交抓取防断流（重点）

平台接口会变（示例：B站评论接口 `ps` 上限从 30 变 20，旧脚本直接 0 条）。现在不靠人工救火：

1. **多候选兜底链**：官方 API → 备用 API → 页面渲染/shadow DOM 文本；任何一条成功就算成功，输出带 `source` 字段。
2. **参数自学习**：遇到 `out of bounds` 等参数错误自动降档（20→10→5）并持久化到 `state/routes.json`。
3. **定时体检**：`social_health.js` 7 项探针（热门/评论/消息中心/黑盒/抖音/微博/贴吧）；全绿不打扰，只在变红/恢复时写 `out/health-alert.md`。
4. **收件箱**：`bili_inbox.js` 查「回复我的/@我的/收到的赞」；查「有没有人互动」用它，不要翻视频评论区。

常用命令（在 `fish/social/` 下）：

```powershell
node social_health.js --quick        # 体检（绿=正常）
node bili_inbox.js all --limit 10    # 回复/@/赞
```

⚠️ 受限会话（微信/QQ 侧 agent）不能直接启动浏览器（`spawn EPERM`），要走浏览器守护进程：`node social.js <脚本> <参数>`。

## 4. 颜文字

- 池：21 类 218 个；插件按轮次从池里随机抽候选注入（避开最近用过的）。
- 规则：一轮最多 1–2 个、按情绪选、别老用同一个；频率可调 `kaomojiEveryTurns`。
- 坑：prompt 不热替换；改池子后要同步副本并重载插件。

## 5. 视频制作（脚手架）

| 脚本 | 用途 |
|---|---|
| `updream_skill.js` | updream 技能画布：开画布 → 过积分弹窗 → 填需求（默认 dry-run） |
| `video_gen.js` | 即梦 Seedance：填视频提示词（默认 dry-run） |
| `updream_manual.js` | 打开画布给用户手动点，脚本检测新图 |
| `open_pages.js` | 打开网页并保持窗口（登录用） |

- 预算护栏：单次 ≤50 积分、每日 ≤150，记账 `state/updream-spend.json`；`--go` 才真正消耗。
- 已知限制：updream 的「产出形式」浮层会拦自动化 → 需手动点确认；即梦参考图上传受 File System Access API 限制 → 手动上传后用 `@图片N` 引用；画布原图是 canvas，只能截屏。
