# 大肥鱼的架构（为什么这样搭）

> 面向：想理解“为什么不是一个软件搞定”的读者。先看 [教程](../tutorials/01-从零养成大肥鱼.md) 跑通，再读本文。

## 一张图

```
用户（微信 / QQ / DSH GUI）
 │
 ├─ 微信 iLink 通道 ── dsh-plugin-weixin ── dsh-weixin-extras（记忆/表情/主动消息）
 │                    └─ 默认人格 + 记忆目录 + 表情目录
 │
 ├─ QQ 官方 Bot 通道 ── @tencent-connect/dsh-qqbot ── DSH Agent
 │                    └─ 人设 directPrompt + memory/ 记忆文件 + /compact
 │
 ├─ QQ 小号（协议端，可选）── NapCat(6099/3000) ── OneBot v11(6199) ── AstrBot(6185)
 │                    └─ 12 插件：表情/空间/资料/主动消息/记忆日记…
 │
 ├─ 浏览器社交（无账号风险）── Playwright + Edge ── B站/小黑盒/抖音/微博
 │
 └─ DSH 技能层：dafeiyu-persona（大肥鱼）、atri-persona（亚托莉，独立）、
                social-browse、qq-life、记忆/文档
```

## 五层分工

| 层 | 负责 | 放在哪 |
|---|---|---|
| **通道** | 收/发消息（微信、QQ 官方、QQ 小号） | DSH 插件 + NapCat/AstrBot |
| **服务** | 协议转换、插件能力（表情/空间/资料/主动消息） | AstrBot、dsh-weixin-extras |
| **人格** | 大肥鱼是谁、怎么说话、边界 | persona prompt + skill + 记忆文件 |
| **数据** | 记忆、日记、表情清单 | `~/.dsh/weixin/`、`.dsh-qqbot/workspace/memory/`、`fish/wechat/` |
| **表达** | 表情图、表情包、颜文字 | 表情目录 + `[表情:名字]` 标记 |

## 为什么不是一个系统

- **官方 QQ Bot 零风控**：走官方协议，但不支持全部“生活能力”（发说说、换头像、逛空间）；
- **协议端（小号）能力强但风险高**：能发说说/换头像/像真人一样操作，代价是可能被风控；
- **微信 iLink 是唯一稳定的微信通道**：但没有原生贴纸/视频发送；
- **浏览器社交不碰账号协议**：只读浏览、发布需人工确认，风险最低。

所以做成**多通道**：聊天走稳的，生活能力走能力强的（并接受风险），冲浪走浏览器。任何一条挂了，其他不受影响。

## 消息怎么走

1. 用户发消息 → 对应通道插件/服务收到；
2. 组装上下文：人格 prompt + 记忆注入（日记/记忆文件）+ 最近对话；
3. 调 DeepSeek（deepseek-flash）生成回复；
4. 出站前处理：拆短句、`[表情:名字]` 换图片、超长改文件、限频；
5. 发回用户；同时写记忆/日记（异步）。

## 为什么记忆要落盘 + 注入

模型上下文会满、会话会换。**只靠模型“记住”一定会失忆**，所以：
- 官方 QQ 鱼：`memory/` 文件 + 人设“每次新会话先读”；
- 微信：插件 memory + 记忆层（dsh-weixin-extras）；
- AstrBot：日记落盘 + 上下文哨兵（90% 自动写）+ 新会话注入最近 7 天。

## 什么情况下该改架构

- 小号风控长期不恢复 → 只保留官方 Bot + 微信；
- 微信 iLink 受限 → 用官方 QQ Bot 为主；
- 需要新能力 → 优先加插件/技能，不动通道。
